# Local workspace

This is an **untracked machine-local storage area**. Only this README is
versioned. See the canonical [Artifact and Local-Test Storage Policy](../docs/system/artifact-storage.md).

| Local folder (create on demand) | Owner and intent |
| --- | --- |
| `downloads/` | All project-initiated prerequisite downloads; retain publisher URL, version and SHA-256 |
| `toolchains/` | Portable Node/npm, Rust/rustup, PowerShell (Git remains an OS prerequisite); not installed app state |
| `cache/` | npm and NuGet caches (Cargo/Rustup are under toolchains) |
| `tmp/` | Temporary files generated by opt-in local developer commands |
| `builds/` | Fresh per-run native-engine build reports and tool-controlled build evidence |
| `packages/` | Fresh immutable staging; Lazy Tester installer candidates are under `packages/lazy-tester/<version>-<commit>-<UTC>/`; not a publishing channel |
| `runs/<UTC>-<shortSHA>-<scenario>/` | `DEV.cmd preflight` writes a metadata-only `manifest.json` after pinned toolchain checks; raw evidence is opt-in only |
| `scratch/` | Disposable research and experiments |
| `private/` | Operator-controlled sensitive material, never publish |
| `evidence/`, `captures/`, `images/`, `runtime/`, `diagnostics/` | Historical local paths: preserve until producers and consumers are reviewed |

All project-owned data belongs beneath this single checkout root. Tool-native
`Development/apps/desktop/node_modules/`, `Development/apps/desktop/dist/`, Rust/Tauri `target/`
and Tauri staging are already **within** that checkout. Existing compiler
caches were retained during source relocation; new Cargo commands through DEV.cmd
use workspace/builds/desktop/target. Source-tree Cargo caches now reside in
archive/compiler-cache-20261026. Automatic approval review rejected recursive
deletion, so reversible archival retained all contents and reclaimed no space.
Active toolchains and build caches remain in place. The pinned native-engine builder and
assembler accept only fresh `workspace/builds/<run>/` and
`workspace/packages/<run>/` output directories. Create their parent folders
locally before running them, keep them ignored, and never reuse a run path.

This storage boundary does **not** relocate Windows-required Microsoft
Visual Studio/WDK, installed drivers/services, Minecraft Education,
Sandboxie Plus, Windows application profiles or protected account data.
No tool may silently move/install/activate any of those components.

The active Lazy Tester has an unsigned installer candidate, not an approved public
release. Root `npm --prefix Development run package:windows` builds from clean committed Local source
and exports only the installer, SHA256SUMS.txt and package-manifest.json. A partial
folder without its completion manifest is not a completed candidate. Use the
separately authorized `DEV.cmd preflight` and `DEV.cmd dev` routes for development;
do not unblock the old VMware NSIS package. Never commit Minecraft game binaries,
account profiles/tokens, Windows machine identifiers, guest disks, private
worlds, signing keys, or unredacted logs. Git ignore is not encryption.

## Read-only developer storage inventory

`DEV.cmd storage report` measures developer output and caches without deleting
anything; `DEV.cmd storage explain` also lists the five largest measured
categories. The tool uses only metadata, excludes Minecraft `Data/` and
protected runtime/backup paths, refuses symlink/junction traversal and stops
at finite entry/time limits. A `PARTIAL` report is a lower bound.
Logical file bytes are not physical occupied space or bytes safe to reclaim.
The initial Cargo `dev`/`test` profile change may trigger a one-time full
rebuild, temporarily leaving old and new artifacts side by side.

The archived 2026-10-26 compiler cache and private App backups remain
protected; they are not automatically deleted. **Only after a successful
native candidate build**, authenticated installer export directories older
than the newest two can be removed, in bounded batches of up to eight.
Active Cargo build/intermediate caches remain reusable.

`DEV.cmd storage plan` is a read-only retention **dry-run** for the historical
compiler-cache archive and versioned, three-file Lazy Tester installer
candidates. It protects the newest three valid candidates and anything
younger than 30 days; older exports are `REVIEW_ONLY` (not deletion-ready).
Unknown or incomplete candidates, untrusted receipts, links, hardlinks,
partial scans and ambiguous directories fail closed. It never scans account
data, app backups, active Cargo targets, or toolchain caches. No `--apply` exists; no disk space is reclaimed by this **read-only plan**.
The successful native package path separately verifies actual installer hashes
and applies the more focused latest-two export policy. Modified, unknown,
linked or partial candidate directories prevent that turnover.

## Setup on Windows x64 (workspace-only)

Run `DEV.cmd bootstrap` **once** from this checkout root. The existing
Windows PowerShell bootstrap downloads the Node and PowerShell ZIPs pinned in
[toolchain.json](../Development/toolchain.json), verifies release SHA-256, provisions the
pinned npm into the portable Node directory, and runs Rustup with a separate
`CARGO_HOME` / `RUSTUP_HOME` under `workspace/toolchains/`. All downloaded
archives and the Rustup checksum/installer remain in `workspace/downloads/`.
The Rustup executable checksum is fetched from its official HTTPS sidecar.
No user/global PATH changes, installer registration or automatic removal of
existing installation data occurs. Existing nonmatching tool installations
fail closed rather than being overwritten.

Then run `DEV.cmd doctor` and `DEV.cmd preflight`. The launcher runs only
`workspace/toolchains/powershell/pwsh.exe`; developer operations require
local Node/npm/Cargo/Rust and use process-scoped npm/NuGet cache, temporary
and home paths under `workspace/`. Direct `npm`, `cargo` or PowerShell
commands outside `DEV.cmd` are **not** guaranteed to share these settings.
Git, Visual Studio/MSVC/WDK and Windows services remain OS prerequisites.

The `setup`, `check`, `test`, and `dev` launcher commands validate the
pinned local toolchain before doing work, even when `doctor` was skipped.
`DEV.cmd doctor` prints the active project, toolchain, download, cache and
temporary directories for explicit inspection. PowerShell bootstrap sets
process-local TEMP/TMP before downloading. Installed Microsoft/Windows system
components remain external prerequisites and are never relocated by `DEV.cmd`.

GitHub Actions remains disabled. Historical debug downloads belong in
`workspace/downloads/`; they are not inputs to the active Lazy Tester installer.

## Approved retirement of one archived compiler cache

AI may propose `DEV.cmd run storage.retire-archive --expect-sha <Local-SHA>
--approve storage.retire-archive` **only after explicit operator approval**.
It uses the existing Cargo footprint scanner to verify the exact old target
`archive/compiler-cache-20261026/target`, requires nonempty replacement
Windows MSVC build artifacts under the canonical active target, and then
runs pinned Cargo `clean --target-dir` scoped to the retired folder only.
Unknown files, links, hardlinks and incomplete scans block cleanup. Nothing
in `workspace/private/`, `Data/`, `App/`, source locks or the active Cargo
target may be removed by this task. Physical space saved remains unverified
until measured on Windows.

`DEV.cmd storage cargo` now includes a separate metadata row for the old
archive's `target` subtree; `storage report` continues to measure the
whole historical archive independently. Neither scan deletes data.

## Cargo target breakdown (read-only)

Run `DEV.cmd storage cargo` to inspect logical bytes in the canonical
Cargo target and historical desktop/runtime-core target folders,
grouped by debug/release and dependency/incremental/build artifacts.
The scanner has entry/time/depth limits; `PARTIAL` means incomplete
metadata, not a proven disk-space number. It does **not** clear caches,
follow links, access `Data/` or private backups, or estimate reclaimable
physical storage.

The `DEV.cmd` local environment now requires exactly the checkout's
`workspace/builds/desktop/target` for `CARGO_TARGET_DIR`. An ambient
override to a second directory fails before cache creation; existing
junctions/reparse points in the target path are refused. Direct shell
Cargo commands bypass this launcher and may still use other targets.
Existing archives remain preserved for explicit retention review.

## Bounded per-pass compiler cache evidence

`DEV.cmd bench:rust` now prints an active-target **logical-byte delta**
around each of its two check passes. A standalone scanner provides
`node Development/tooling/storage/cargo-footprint.mjs --active-json` for
bounded aggregate-only snapshots; it does not expose filenames, game data
or a general inventory of installed-user paths. The 15-second/250,000-entry
limit yields `UNKNOWN` rather than a false full measurement. Scans occur
**outside** the build stopwatch and do not clean or relocate any cache.
These are not physical storage savings or an automatic retention decision.

`DEV.cmd` additionally refuses ambient `CARGO_BUILD_TARGET_DIR` and
`CARGO_BUILD_BUILD_DIR` overrides that differ from the canonical
`workspace/builds/desktop/target`. Cargo itself also accepts such
settings outside the launcher, so direct terminal builds can still create
extra output roots.

## Scoped checks and optional timing

`DEV.cmd check:frontend` runs only Svelte/TypeScript typecheck and
Vitest. `DEV.cmd check:rust` uses explicit Windows MSVC-target Cargo
checks for desktop and runtime-core; it does not run Rust tests or
build the installer. The complete `DEV.cmd check` / `DEV.cmd preflight`
routes remain unchanged. The quick Rust route aligns target-directory
layout with Tauri development, but feature/profile differences can still
duplicate artifact caches and the first run can temporarily increase disk
usage.

`DEV.cmd bench:frontend` and `DEV.cmd bench:rust` each run the
corresponding targeted check twice, only with a clean, pinned `Local`
revision and the portable toolchain. Both passes **reuse whatever cache
exists**. The first is not verified cold; the second is not guaranteed
warm. Durations appear on the console only. No cache reset, extra
target directory, automatic report log, installer or Minecraft launch
is performed. The benchmark may compile and grow the existing target;
use the read-only `storage report` separately when storage is constrained.

## Preserved local history

workspace/archive contains explicitly reviewed local archives. The stale generated
Svelte checker tree is under archive/layout-20261026. Existing loose logs, scripts,
screenshots and opaque probe directories remain preserved at their original paths:
they have not been certified free of account/machine data or live references.
No archive or cleanup command may infer that those entries are disposable.
